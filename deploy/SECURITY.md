# Deployment security boundaries

Delivery validation resumed on 3 November 2026. Refreshed audits flagged fourteen pypdf advisories in 6.20.1 and three Next.js advisories in 16.3.8. Both Python manifests now pin [pypdf 6.21.4](https://github.com/py-pdf/pypdf/releases/tag/6.21.4), and the frontend pins [Next.js 16.4.4](https://github.com/vercel/next.js/releases/tag/v16.4.4) with matching lint configuration. These replace the earlier October fixes. CI audits the locked Python runtime and the npm production graph; development-only advisories remain separately tracked below. Audit results describe the package advisory database at the time of each run, not a permanent vulnerability-free guarantee.

The development stack binds PostgreSQL, the API and the frontend to localhost. The production stack exposes only a localhost gateway at port 8080, intended to sit behind an HTTPS ingress. Set PUBLIC_ORIGIN to that exact HTTPS origin. Secure cookies are enabled in production. Do not expose the development database or Ollama directly to the Internet.

The API role is not the table owner, a superuser, or a BYPASSRLS role. Workspace content tables apply PostgreSQL row-level policies. Authentication derives the database identity from a hashed opaque session cookie. Reader accounts can query permitted content and create private conversations; editors can manage documents; administrators manage workspace memberships. Conversations are private to their author, including from other workspace administrators through the application API.

The worker has a separate, explicitly privileged role for ingestion across workspaces. The migration service alone receives owner credentials. Compromise of the backend or database credentials is outside the protection provided by application identity settings; bound SQL parameters, network isolation and secret handling remain necessary.

Sessions expire after eight hours and are revoked on password changes/recovery. Mutations require a per-session CSRF header; unexpected browser origins are rejected. Passwords use independently salted scrypt hashes. Initial credentials are generated locally; no password is committed to source. Optional OIDC SSO uses Authlib and Keycloak with provider-managed MFA. SSO-only accounts cannot use local password recovery/login. Security certification is not provided.

Self-service registration is enabled by default in local Compose and disabled by default in production Compose (`ALLOW_REGISTRATION`). It is rate limited, creates a private workspace, and requires an email verification link. Expiring action tokens are hashed and single-use. Local Mailpit captures test mail; production SMTP must be explicitly configured. Invitations require a verified matching email and grant only reader/editor roles. Pre-existing and administrator-provisioned accounts remain explicitly approved by their administrator. Reader and editor memberships use the same local login endpoint as administrators.

Document restrictions are enforced by PostgreSQL restrictive row policies across documents, versions, chunks and jobs. Administrators/uploaders retain access. Stored cited answers are rechecked on fetch/export/replay. Already delivered data cannot be recalled and ongoing streams are not retroactively erased. See `OPEN_SOURCE_FEATURES.md` for scope and checks.

Original PDFs use opaque storage keys, and every file request checks document access. Deleted documents are excluded from retrieval and file serving. Trash retains original data until an explicit retention purge. Back up both the database and the original-file volume. Encrypt backups and the underlying database/storage disks using your hosting platform; application-level encryption-at-rest is not claimed.

The answer model receives only permission-filtered excerpts, and no application tools or credentials. Prompts and evaluation cases address malicious document instructions, but prompts do not eliminate prompt injection or guarantee factual support for every claim. Retain human review for consequential answers.

Prometheus metrics use a separate bearer token and aggregate labels. Default logs omit passwords, session tokens, prompts and document text. Restrict access to metrics, audit logs and evaluation output. Alert rules are provided; outbound notification destinations are intentionally not configured.

Before rollout: configure HTTPS and your secret manager, rotate bootstrap credentials, validate restore procedures, run representative domain evaluations and load tests, configure retention, and complete your organization's security review. These requirements depend on the actual environment and cannot be established by a local smoke test.

Dependency audit on 3 November 2026: the patched Python lockfile and npm runtime graph reported zero known vulnerabilities. The CSS build parser remains overridden to postcss-selector-parser 7.1.7. A compatible Zod update also removed a development-only high advisory. The complete npm graph still reports sixteen moderate findings propagated through the lint toolchain from [minimatch GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249). These dependencies process development file patterns and are absent from the standalone runtime. npm's proposed force fix downgrades ESLint/Next lint configuration to incompatible old releases; it is not applied. Track compatible upstream toolchain updates, retain CI timeouts, and do not claim a zero-advisory development dependency graph. Earlier October audit results are historical.
